# Nishaaj Islam — Portfolio Site (static + build step)

This replaces the PHP site (`icsdiscover_site_052942.zip`) with a static site
generated by a small Node build script. **No PHP, no server, no runtime
dependencies** — deployable free on Vercel with automatic HTTPS.

## Why this version instead of a plain static HTML file

The first pass converted your pages to plain static HTML, but that meant
the navbar (links, cheat-sheet CTA) was hardcoded separately into each
page — so toggling a link on/off meant editing HTML in multiple places.
That broke the actual workflow `header.php` gave you: **edit one file,
every page updates**.

This version restores that. `site.config.js` is the single source of
truth — the direct replacement for the `$config` array you used to edit
inside `header.php` — and `build.js` generates every HTML page from it.
Edit the config, run `node build.js` (or let Vercel run it on every
deploy), and the change appears everywhere it should.

## What's centrally controlled from `site.config.js`

| What | How to change it |
|---|---|
| Nav links (Tutorials, Github, LinkedIn, Contact, About) | Edit the `navLinks` array. Set `enabled: false` to hide a link from **every page** instantly, or add a new object to add a link everywhere at once. |
| The cheat-sheet CTA button | One flag: `cheatsheetCTA.enabled`. This replaces having to maintain a second copy of the header (`header_without_cheetsheetlink.php`) — flip the flag instead of swapping files. |
| Project cards | Edit the `projects` array. `online: true` → card links through a generated countdown/redirect page (`/go/<code>.html`); `online: false` → links to the green-earth "offline" page, same as before. `enabled: false` pulls a card off the homepage without deleting its data. |
| Footer text, hero copy, tech badges | `footerText` / `person` fields. |
| Resume sections (About, Education + coursework, Experience, Skills) | Edit the `resume` object. Rendered below Featured Projects. A project with `type: 'static'` renders as a non-clickable card. |
| Navbar CTA (now **Download Resume**) | `cheatsheetCTA` — points at `assets/Nishaaj_Islam_Resume.pdf`. Replace that PDF to update the download. |

After any edit, run:
```bash
node build.js
```
This regenerates `dist/` — `index.html`, `green_earth_page.html`, and one
`/go/<code>.html` redirect page per online project — from the config.
Vercel runs this same command automatically on every push (see below), so
in practice you just edit `site.config.js`, commit, and push.

## What changed vs. the original PHP

| Original (PHP) | Now | Why |
|---|---|---|
| `header.php` shared markup + `$config['sites']` | `site.config.js` (data) + `partials.js` (render functions) + `build.js` (orchestrator) | No PHP on static hosts; this is the same "edit once, applies everywhere" pattern, just resolved at build time instead of request time |
| `index.php` homepage + `?site=code` redirect | `index.html` (pre-rendered cards) + a real static page per project at `/go/<code>.html` | Each redirect is now its own crawlable, JS-independent page (instant `<meta refresh>` + a countdown UI for parity) instead of one page branching on a query string |
| `green_earth_page.php` | `green_earth_page.html`, generated from `partials/green-earth.*` | Straight conversion, same visuals |
| `header_without_cheetsheetlink.php` | Removed — replaced by `cheatsheetCTA.enabled` flag in config | One flag instead of a whole duplicate file to maintain |
| Bootstrap/Bootstrap Icons/Google Fonts via CDN `<link>` tags | Self-hosted under `vendor/` | Zero external dependency — the site fully renders even if a CDN is down, and there's nothing to break under InfinityFree-style restrictions again |
| `favicon.ico` used as the navbar logo `<img>` | `logo_small.png` used for the navbar logo; `favicon.ico` kept only as the actual browser tab favicon | `.ico` files render unreliably inside an `<img>` tag across browsers/contexts — this was caught during testing and fixed |

All copy, links, colors, animations, and the project-card/redirect UI are
preserved exactly — this is a like-for-like conversion, not a redesign.

## Folder structure

```
/
├── site.config.js          ← EDIT THIS to change links/projects/CTA
├── partials.js              (render functions — rarely needs editing)
├── build.js                 (run: node build.js)
├── partials/
│   ├── green-earth.css
│   ├── green-earth.body.html
│   └── green-earth.script.html
├── css/site.css             (shared visual styles)
├── js/site.js                (navbar scroll effect + scroll-reveal animation)
├── vendor/                   (self-hosted Bootstrap, Bootstrap Icons, fonts)
├── assets/                   (favicon, logo, pdf, the flowchart page — copied into dist/ as-is)
├── vercel.json               (tells Vercel to run `node build.js`, output `dist/`)
├── package.json
└── dist/                     (generated output — this is what gets deployed)
```

## Deploy to Vercel for free (5 minutes)

1. Push this whole folder (including `dist/` isn't required — Vercel
   rebuilds it — but it's fine to leave it) to a GitHub repo:
   ```bash
   git init
   git add .
   git commit -m "Static portfolio site v2"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<repo-name>.git
   git push -u origin main
   ```
2. Go to **vercel.com** → sign in with GitHub → **Add New Project** → select the repo.
3. Framework Preset: **"Other"**. Vercel reads `vercel.json`, runs
   `node build.js`, and serves `dist/` — no other config needed.
4. Click **Deploy**. You'll get a free `https://<project-name>.vercel.app`
   URL with a valid, auto-renewing SSL certificate.
5. *(Optional)* Add a custom domain under Project → Settings → Domains.

Every future `git push` to `main` re-runs the build and redeploys
automatically.

### Alternative: skip the build, deploy `dist/` directly
If you'd rather not have Vercel run a build step at all, you can `cd dist`
and drag *that* folder into Vercel/Netlify's dashboard directly. You'll
just need to re-run `node build.js` and re-upload `dist/` yourself
whenever you edit `site.config.js`.
